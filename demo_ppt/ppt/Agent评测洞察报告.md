# Agent 评测洞察报告

# 1 评测是 Agent 的核心，要同时看结果、过程与成本

## 1.1 为什么必须做完整链路评测

Agent 是概率系统，无法做到 100% 成功，必须验证「感知 → 规划 → 记忆 → 工具调用」的完整链路。

| 原因 | 说明 |
| --- | --- |
| 不确定性 | 同一输入多次运行结果可能不同，单次成功不代表可用 |
| 误差累积 | 每一步的小偏差会沿链路放大，最终导致任务失败 |
| 风险外溢 | 越权、误删、错误发布等代价，远高于「答错一道题」 |

不能稳定重跑的评测，结论都不可信——**可复现是评测的第一性原理**。

## 1.2 三个核心指标缺一不可

| 指标 | 回答的问题 | 关键信号 |
| --- | --- | --- |
| Outcome（结果） | 能不能用 | 任务成功率、产物可用率、部分完成率 |
| Trace（过程） | 为什么 | 工具选择、参数合法性、无效重试、纠错能力 |
| Experience & Expense | 值不值得用 | 单成功任务成本、端到端时延、人工介入率 |

Outcome 决定「能不能用」，Trace 解释「为什么」，Experience & Expense 决定「值不值得、敢不敢托付」。

# 2 评测集与评分决定结论是否可信

## 2.1 评测集要真实、分层、可复现

评测集是评测体系的地基，优先保证「真」和「分层」，再逐步扩规模。

1. **核心任务**：业务最关键、最高频的流程。
2. **真实任务日志**：从线上请求、工单、对话中采样，贴近真实分布。
3. **历史任务日志**：用于回归，保证旧问题不复发。
4. **边界问题**：模糊输入、极端输入、异常状态，验证鲁棒性。

补充原则：正反用例并重（负例覆盖幻觉、越权、无效调用、提示注入）；按任务类型与风险分层；打版本号并保留 holdout，防止过拟合；起步用 30–50 条高质量真实任务。

## 2.2 评分要脚本优先、模型补充、人工兜底

| 方式 | 适用 | 注意事项 |
| --- | --- | --- |
| 脚本评分 | 断言、单测、状态检查 | 最客观可复现，可进 CI |
| 模型评分 | 开放式产出的过程打分 | rubric 要明确，警惕位置与长度偏差 |
| 人工评分 | 专业性强、高歧义问题 | 统一评分卡，用一致性指标校准 |

推荐瀑布式组合：脚本先筛 → 模型补充 → 人工兜底；模型评分必须定期用人工标注校准，避免评分器漂移。

# 3 按能力链路拆解，能力评测与回归测试并重

## 3.1 按能力拆解，才能定位短板

只看总成功率无法定位问题，应按感知、规划、记忆、工具逐段建立指标。

| 能力 | 评测重点 | 典型指标 |
| --- | --- | --- |
| 感知 | 意图识别与歧义澄清 | 意图准确率、槽位 F1、歧义处理率 |
| 规划 | 分解合理性与失败重规划 | 计划有效率、重规划成功率、收敛步数 |
| 记忆 | 多轮与长对话信息保持 | 短期保持率、长期召回率、前后一致性 |
| 工具 | 调用正确性与异常恢复 | 工具选择准确率、参数正确率、异常恢复率 |

这样总成功率下降时，能快速判断是哪一环退化，从而定向修复。

## 3.2 能力评测看边界，回归测试看稳定

| 维度 | 能力评测 | 回归测试 |
| --- | --- | --- |
| 目标 | 探索能力上限 | 保证不退化 |
| 指标 | pass@k（k 次至少 1 次成功） | 固定集成功率、pass^k（k 次全部成功） |
| 结论 | 能不能做 | 敢不敢上 |

统计纪律：重复采样并报告均值与方差；分数配置信区间；对比版本时使用同一任务集与同一评分器，避免口径漂移。

# 4 对标公开基准，先复现再规模化

## 4.1 公开基准只作参考，自建评测才是准绳

| 基准 | 侧重 |
| --- | --- |
| SWE-bench | 真实仓库 issue 修复 |
| WebArena | 浏览器环境长程任务 |
| OSWorld | 桌面应用多步骤操作 |
| τ-bench | 工具调用与多轮对话 |
| GAIA | 通用助手综合任务 |

公开任务可能已被训练数据污染，且与业务分布存在偏差，不能替代自有业务评测集。

## 4.2 落地顺序：先能复现，再谈规模

1. 选一条高价值流程，采集 30–50 条真实任务，定义完成标准。
2. 搭环境复现与脚本评分，形成可重跑的流水线。
3. 补充过程、成本、时延与人工介入等维度。
4. 接入 CI 回归与线上监控，把失败样本回流成新任务。
5. 引入模型评分与人工校准，逐步扩展任务集与场景。

常见陷阱：数据污染、榜单调优、环境漂移、评分器偏差、只报平均分、只测顺境。

> 不要问「这个 Agent 多少分」，要问「在什么任务上、以什么成本、稳定地交付了什么结果、失败时是否可控」。
