# 示例规则：代码提交规范

> 示例规则：演示 rules 的标准写法。

## 规则名

代码提交规范

## 适用范围

所有代码仓库的 `master` 分支与功能分支。

## 级别

必须

## 约束条目

1. 提交前必须通过类型检查与单元测试。
2. 提交信息说明「做了什么、为什么」，不写无意义内容。
3. 一次提交只做一件事，避免混合无关改动。
4. 禁止提交密钥、令牌、口令、私钥与带凭据的 URL。
5. 禁止提交构建产物、依赖目录、日志与临时文件。
6. 提交前检查 `git status`，只暂存本次涉及的文件。

## 例外

- 紧急修复可先提交最小改动，事后补充测试与说明。
- 例外需在提交信息中注明原因。

## 违规处理

- 发现敏感信息：立即移除、轮换凭据，必要时清理历史。
- 发现无关文件：从提交中移除并补充忽略规则。
- CI 失败：修复后重新提交，不跳过检查。
