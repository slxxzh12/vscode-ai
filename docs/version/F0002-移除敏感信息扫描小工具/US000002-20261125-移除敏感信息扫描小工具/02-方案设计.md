## 3. 兼容与清理

1. **持久化数据**：`localStorage` 键 `devflow-security-scan-dirs` 删除后不再读取，残留无害；如需干净可提示用户清理，不强制。
2. **历史页签/深链**：`ToolId` 去掉 `'security'` 后，历史 `t:security` 或 URL 需回退到安全页面。实施时确认 `useCenter` / `TerminalView` 对未知工具 id 的容错；若无则补「未知 tool → 忽略/回退」。
3. **类型收敛**：改 `ToolId` 后 TypeScript 会暴露所有残留引用，按报错逐项清理，避免漏删。
4. **构建产物**：删除后重新 `npm.cmd run build:web` 再打包，确保 `web/dist` 与绿色包不含该工具。

## 4. 实施顺序

1. 后端：删 `http-api.js` 的 import 与 `/api/security/scan` 路由；删 `server/security/scan.js`；删 `server/test/security-scan.test.js`。
2. 前端：删 `SecurityTool.vue` 与 `tools/security/`；改 `catalog.ts`、`TerminalView.vue`、`ToolSidebar.vue`、`MiniTools.test.ts`。
3. 词条：中英同步删除。
4. 文档：删 `docs/knowledge/security-scan.md`。
5. 校验。

## 6. 回滚

- 回滚到删除前提交即可；无数据库变更。
- 若误删代码统计页签，按 `SecretScan.vue` / `server/secret-scan.js` / `codestat.scan.*` 恢复（本方案不涉及）。

## 7. 风险

- **同名误删**：严格按第 1、2 节清单，不碰 `SecretScan.*` / `secret-scan.js` / `codestat.scan.*`。
- **外部调用**：仓库外若调用 `/api/security/scan` 会 404；仓库内无其他调用方。
- **历史页签**：需确认未知工具 id 的容错。
