# version（版本文档）

采用「特性 → 方案」两级目录：

- `docs/version/<特性编号-特性名>/`：一个特性一个文件夹，如 `F0001-用户管理/`。
- 其下每个方案一个文件夹：`US编号-日期-名称/`，如 `US000001-20260315-增加一个用户管理系统/`。
- 特性编号与方案目录的映射维护在 `docs/version/features.md`。

一个方案一个文件夹；编号唯一且不复用；同一特性可包含多个方案。方案文件夹内放 README、需求分析、方案设计、任务拆分、验收清单、构建发布。

## 自动检测与代码流水线

流水线支持两种布局（见 `server/pipeline/us-detect.js`）：

- `docs/version/US…/` 直接子目录；
- `docs/version/<特性编号-特性名>/US…/` 一层特性文件夹。

只识别一层特性文件夹（`F` + 4 位数字），不要再多套层级。
