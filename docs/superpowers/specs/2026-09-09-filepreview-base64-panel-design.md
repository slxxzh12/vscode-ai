# 设计：FilePreview Base64 结果面板

日期：2026-09-09

## 背景

`web/src/components/FilePreview.vue` 已存在 Base64 功能：顶部工具条有一个 `⟐ Base64 ▾` 下拉菜单，含「Base64 编码」「Base64 解码」两项。现行为：对编辑器选中内容（无选中则整个文件）编码/解码 → 结果复制到剪贴板 → 顶部闪一行 `已编码并复制：…` 提示。结果不落屏展示，复制静默污染剪贴板。

## 目标

点击 Base64 后，在编辑器下方多出一块结果栏目，把编码/解码内容展示出来供查看与手动复制；不再自动写剪贴板。

## 交互

- 顶部工具条把 `⟐ Base64 ▾` 下拉按钮改为单个开关按钮 `⇆ Base64`（显隐条件与现 `canB64` 一致：文本文件 + 加载成功 + 编辑器可见）。
- 点击打开 → 编辑器下方出现结果面板；再点关闭。关闭或切换文件时面板状态重置。
- 移除旧的「自动复制到剪贴板 + 顶部闪提示」逻辑。

## 面板布局

结果面板横跨编辑器下方，总高约 220px（flex 布局，编辑器让位），内部左右并排两列：

### 左列：Base64 编码（只读 · 实时刷新）

- 数据源：编辑器当前内容 —— 有选区跟随选中部分，无选区取整个文件。
- 随编辑器输入 / 选区变化实时刷新。
- 展示在可滚动 `<pre>` 中。
- 按钮：`复制`、`清空`。

### 右列：Base64 解码（可编辑输入 · 实时解码）

- 一个可粘贴 / 可编辑的输入框。
- 输入任意 base64 → 下方实时显示解码结果；非法 base64 时列内显示红字错误，不影响编辑器。
- 展示在可滚动 `<pre>` 中。
- 按钮：`复制`、`清空`、`编码结果→解码`（把左列编码结果一键填入右列做往返验证）。

## 错误处理

- 编码使用现有 `btoa(unescape(encodeURIComponent(src)))` 路径（中文安全）。
- 解码使用现有 `decodeURIComponent(escape(atob(src.trim())))` 路径；异常捕获后列内红字提示，不弹窗。

## 技术要点

- 纯前端改动，仅涉及 `web/src/components/FilePreview.vue`。
- 实时刷新复用手动输入监听时机：编辑器已有 `docChanged` 更新 `raw`；选区变化可借 CodeMirror `updateListener` 中 `u.selectionSet` 判断触发列刷新。
- 复制沿用现有 `b64Copy` 降级方案；输出量小时无需虚拟滚动，可滚动 `<pre>` + `overflow: auto` 即可。
- 沿用仓库现有 Vue SFC / CSS 变量（`var(--bg1)`、`var(--bd)` 等）风格。

## 测试

- 不新增组件测试文件：仓库无 FilePreview 组件测试先例，编解码纯函数逻辑沿用既有路径。提交前跑 `npm.cmd run typecheck` 与 `npm.cmd test` 确认无回归。

## 范围外（YAGNI）

- 不做解码输入源切换（如“解编辑器内容 vs 解编码结果”）。
- 不做分片 / 流式处理大文件。
- 不做 base64 变体（urlsafe 等）。
