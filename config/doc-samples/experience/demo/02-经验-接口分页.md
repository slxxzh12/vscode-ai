# 经验：列表接口分页要固定排序

> 示例文档：演示经验库的标准写法。

## 场景

用户列表翻页时，同一用户在第 1 页和第 2 页重复出现，偶尔又漏掉。

## 问题

分页结果不稳定，刷新后顺序变化。

## 根因

查询只按 `created_at` 排序，多条记录时间相同，数据库返回顺序不固定。

## 解决方案

1. 排序改为 `created_at DESC, id DESC`，保证唯一顺序。
2. 前端翻页参数保持不变。
3. 补充分页边界测试。

## 验证

- 连续翻页无重复、无遗漏。
- 新增数据后旧页数据不跳动。

## 预防

- 所有分页接口必须带唯一键作为次级排序。
- 代码评审清单增加分页稳定性检查。
