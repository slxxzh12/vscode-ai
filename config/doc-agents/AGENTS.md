## 方案文档规范（DevFlow 代码生成流水线）

本仓库是文档仓，所有方案统一放在 `docs/version/` 下，一个方案一个文件夹，不要把多个方案混在一起，也不要放到其他目录。

### 目录与命名

- 目录：`docs/version/<方案编号>-<日期>-<方案名称>/`
- 命名格式：`方案编号-日期-方案名称`
  - 方案编号：`US` + 6 位数字，例如 `US000001`
  - 日期：`YYYYMMDD`，例如 `20260315`
  - 方案名称：简短中文或英文，不能包含 `/ \ : * ? " < > |`
- 示例：`docs/version/US000001-20260315-增加一个用户管理系统/`

### 文件格式

方案文件夹内按以下顺序编写，缺少的章节要显式写「无」并说明原因：

| 文件 | 内容要求 |
| --- | --- |
| `README.md` | 方案概览、目录说明、变更历史 |
| `01-需求分析.md` | 背景、目标、范围、验收标准 |
| `02-方案设计.md` | 总体架构、数据模型、接口设计、权限与安全、异常处理、风险与取舍 |
| `03-任务拆分.md` | 可执行任务、依赖关系、排期 |
| `04-验收清单.md` | 验收项、验收结果、回归范围 |

### 编写要求

- 方案编号与日期一旦确定不要修改；需求变更时更新对应文件，并在文末追加变更记录。
- 方案内容必须能指导开发：接口写清方法/路径/参数/返回/错误码，数据模型写清表名/字段/索引。
- 涉及权限、安全、数据迁移、兼容性的改动必须单独成节说明。
- 引用其他文档使用仓库内相对路径，禁止写本机绝对路径。
